Ringkasan

Resik (Resik = Bersih) adalah aplikasi Bank Sampah Digital yang dibangun untuk mengatasi dua permasalahan utama dalam pengelolaan sampah di Indonesia: minimnya edukasi pemilahan sampah dan tidak adanya platform terpusat yang menghubungkan masyarakat dengan bank sampah. Aplikasi ini menghubungkan masyarakat sebagai penyetor sampah dengan pengelola bank sampah sebagai verifikator, sehingga seluruh proses — dari penjemputan, penimbangan, hingga pembayaran — tercatat secara digital dan transparan.

Tujuan jangka panjang Resik adalah mengubah perilaku masyarakat terhadap pengelolaan sampah: dari sekadar membuang menjadi memilah dan memanfaatkan nilai ekonomisnya. Target ini dicapai melalui tiga pilar: edukasi (panduan kategori sampah dan harga per kg), transparansi (riwayat transaksi real-time dan dompet digital), serta insentif (pembayaran langsung ke dompet digital dan leaderboard kontribusi).

Metode yang digunakan adalah pengembangan full-stack dengan pendekatan berorientasi objek. Backend dibangun dengan Spring Boot 3.2.5 dan PostgreSQL 16, menerapkan pewarisan (inheritance) pada entitas User dengan tiga peran: Admin, Petugas, dan Masyarakat. Aplikasi Android dibangun dengan Kotlin + Jetpack Compose menggunakan pola MVVM, sedangkan aplikasi desktop admin dibangun dengan Java + JavaFX 21. Komunikasi antar-komponen menggunakan REST API dengan autentikasi JWT dan WebSocket untuk fitur chat real-time.

Kegiatan yang telah dilakukan meliputi: analisis kebutuhan, desain arsitektur tiga-tier (Android Client — Backend API — Desktop Admin), implementasi CRUD lengkap untuk data sampah dan lokasi bank sampah, sistem penjemputan dengan status real-time (Menunggu → Dijadwalkan → Diproses → Selesai), sistem penimbangan dengan kalkulasi harga otomatis dan transfer ke dompet digital, serta deployment ke VPS menggunakan Docker Compose. Aplikasi telah diuji dengan akun demo pada server produksi dan siap digunakan.

Implementasi Pemrograman Berorientasi Objek

Penerapan konsep OOP pada setiap lapisan arsitektur aplikasi.

Aplikasi ini menerapkan konsep OOP secara menyeluruh pada setiap lapisan arsitektur:

Inheritance (Pewarisan)

Kelas User merupakan abstract class dengan strategi SINGLE_TABLE. Tiga subclass mewarisi seluruh atribut dan method dasar:

  • Admin — pengelola aplikasi (role: ADMIN)
  • Petugas — petugas penjemputan (role: PETUGAS)
  • Masyarakat — penyetor sampah (role: MASYARAKAT)

Encapsulation (Pembungkusan)

Semua entitas (Penjemputan, Sampah, Transaksi, DetailPenjemputan, LokasiBankSampah, Notifikasi) menggunakan modifier private untuk atribut dan method getter/setter publik untuk akses terkontrol.

Polymorphism (Polimorfisme)

Method abstrak getRole() pada User di-override oleh setiap subclass untuk mengembalikan role spesifik. Enum PenjemputanStatus dan TransaksiStatus menggunakan @Enumerated(EnumType.STRING) untuk fleksibilitas.

Composition & Association

Penjemputan memiliki relasi @OneToMany dengan DetailPenjemputan dan @OneToOne dengan Transaksi. @ManyToOne menghubungkan Penjemputan dengan User (penyetor) dan User (petugas).

Login dan Logout

Login: Pengguna memasukkan email dan password. Sistem mengirimkan JWT token yang disimpan secara lokal dan digunakan untuk semua permintaan API selanjutnya.

Logout: Pengguna menekan tombol logout (di desktop: top bar; di Android: menu profil). JWT token dihapus dari penyimpanan lokal dan pengguna dikembalikan ke halaman welcome/login.

Implementasi OOP: Pewarisan @Inheritance(strategy = InheritanceType.SINGLE_TABLE) pada kelas User dengan @DiscriminatorColumn memungkinkan tiga peran disimpan dalam satu tabel dengan discriminator role.

11. Pertanyaan yang Sering Diajukan (FAQ)

PertanyaanJawaban
Bagaimana jika salah memasukkan data penjemputan? Penjemputan yang masih berstatus MENUNGGU dapat dibatalkan. Hubungi admin untuk pembatalan. Buat penjemputan baru dengan data yang benar.
Apakah data tetap tersimpan setelah aplikasi ditutup? Ya. Semua data tersimpan di server VPS (PostgreSQL). Saat buka kembali, data akan otomatis dimuat dari server.
Bagaimana cara menemukan riwayat transaksi saya? Buka menu "Riwayat" di aplikasi Android. Semua transaksi tampil dengan filter kategori. Di Desktop, buka menu "Riwayat Setoran".
Apa yang dilakukan jika muncul error? Catat pesan error, periksa koneksi internet, coba refresh/restart aplikasi. Jika berlanjut, hubungi admin dengan screenshot error.
Berapa lama penjemputan diproses? Admin akan menjadwalkan penjemputan (status DIJADWALKAN), lalu petugas datang sesuai jadwal (status DIPROSES). Setelah penimbangan & konfirmasi, status menjadi SELESAI.
Apakah saldo dompet bisa ditarik? Saat ini saldo dompet digital berfungsi sebagai catatan pembayaran. Fitur penarikan ke rekening bank belum tersedia (lihat Keterbatasan).
Apakah aplikasi bisa digunakan offline? Tidak. Aplikasi memerlukan koneksi internet untuk berkomunikasi dengan server VPS.
